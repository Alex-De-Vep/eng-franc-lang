# Irina Purtova — frontend

Мультиязычный сайт преподавателя на Vite, HTML, CSS и JavaScript с PHP 8.2 API для контактных форм.

```bash
npm install
npm run dev
npm run test
npm run build
npm run build:timeweb
```

Основной контент, ссылки и заглушки находятся в `src/data/content.js`. Временные Figma URL в коде не используются: изображения и SVG хранятся в `public/assets`.

## Cookies и MyTracker

Используется только MyTracker / Top.Mail.Ru **3808064**. SDK загружается только
после явного согласия посетителя. До выбора и после отказа запросов аналитики нет.
В HTML отсутствуют безусловные скрипты и noscript-пиксели.

Настройки: VITE_MYTRACKER_ID=3808064, VITE_MYTRACKER_ENABLED=true.
Флаг false отключает сбор. VITE-переменные не должны содержать секреты.
На обоих доменах используется mytopf.com с последовательным резервным
подключением top-fwz1.mail.ru при ошибке. Просмотр отправляется один раз
после успешной загрузки SDK, URL и referrer очищаются от query и hash.
В кабинете автоматические события и Ecommerce должны оставаться выключенными;
изменение автоматических событий может применяться до четырёх часов.
Код сайта не передаёт UserID, цели, email, комментарии и ответы анкеты.

Выбор хранится 180 дней отдельно на каждом домене. Изменение ID, доступности
или состава счётчиков требует нового выбора. Старое согласие на два счётчика
не используется для текущей интеграции. Настройки доступны в футере.
При отзыве сначала сохраняется отказ, удаляются доступные tmr_lvid, tmr_lvidTS,
tmr_detect, затем страница обновляется, если SDK уже запрашивался. Это завершает
его таймеры; несохранённый ввод может потеряться. Отзыв синхронизируется между
вкладками. Если localStorage недоступен, новая страница снова спросит выбор.
Сторонние cookies и уже переданные на сервер данные этим не удаляются.

Проверка Chrome: до согласия запросов нет; после согласия SDK и один просмотр
получают HTTP 200; после отказа запросы прекращаются. Режим ?tmr_debug=1
выводит Page view и номер счётчика в консоли. Успешный HTTP-ответ не заменяет
подтверждение обработки данных в отчётах кабинета.

## Политика конфиденциальности

Отдельные страницы `/ru/privacy/`, `/en/privacy/`, `/fr/privacy/` включаются
в production-сборку и архив Timeweb. Полный текст формируется в HTML на этапе
сборки и доступен без JavaScript. Переключатель языка остаётся на документе,
ссылка назад ведёт на лендинг того же языка. Формы открывают документ в новой
вкладке, чтобы не терять введённые данные; ссылка есть также в футере и баннере.

Тексты находятся в `src/data/privacy.js`, общий шаблон —
`src/components/PrivacyPage.js`. Оператор: **Пуртова Ирина Евгеньевна**, физическое
лицо, Россия; обращения: **ipurtova.37@gmail.com**. Домашний или почтовый адрес
не выдуман и не добавлен. Информация о cookies включена в раздел `#cookies`,
отдельный Cookie Policy не требуется для навигации. Упоминание несуществующей
оферты из согласия формы удалено; согласие на аналитику остаётся независимым.

Это **проект для юридической проверки**, а не гарантия соответствия закону.
Страницы помечены `noindex, follow` и содержат заметку о статусе проекта.
Перед публичной выкладкой необходимо:

- Проверить требования к адресу оператора, тексту отдельного согласия на
  обработку данных и уведомлению Роскомнадзора.
- Проверить локализацию и трансграничную передачу при использовании Gmail,
  Telegram/Salebot, действующие условия и фактические настройки этих сервисов.
- Организовать удаление заявок из всех используемых хранилищ, уточнить сроки
  технических журналов и резервных копий; не подменять их сроками заявок.
- После проверки заменить заметку о проекте утверждённой редакцией, обновить
  дату документа и при необходимости снять `noindex`.

Согласованный срок для несостоявшихся заявок — **90 дней после последнего
контакта**. Он относится к содержимому заявок в почте и Telegram/Salebot и
должен быть обеспечен вручную или отдельной автоматизацией. Этот баннер не
удаляет письма, сообщения и анкеты; сроки служебных файлов PHP-бота не меняет.
Счётчики не являются получателями содержимого заявки из нашего кода.
Сроки аналитики нужно отдельно проверить в настройках и документации сервисов.

## Выкладка на Timeweb

### Техническое SEO и языковые домены

Основные адреса: русский — `https://iripurtova-languages.ru/ru/`, английский —
`https://iripurtova-languages.com/en/`, французский —
`https://iripurtova-languages.com/fr/`. То же распределение действует для страниц
политики. Адреса HTML и языковых ссылок задаются в `src/siteUrls.js`;
соответствие статических robots/sitemap этим адресам проверяется тестами.
`hreflang` взаимно ссылается на все три канонических версии; `x-default` остаётся
английским, как и язык корня `.com`. Это не меняет приоритет русской версии на `.ru`.

`build/landingPages.js` при сборке и в Vite dev формирует полный HTML лендинга
из тех же компонентов, что использовались в браузере (`src/renderLanding.js`).
Заголовки, описания, FAQ и языковые ссылки доступны роботу без выполнения JS.
Браузер использует готовые узлы и подключает обработчики форм, модалок и слайдеров,
не рисуя страницу заново. Баннер cookies и аналитика инициализируются отдельно
только в браузере; текущее поведение согласия не меняется.
Без JS кнопки форм выключены, доступна ссылка на email; формы никогда не
используют GET для передачи персональных данных. Год в футере обновляется и
в браузере, поэтому не зависит только от даты сборки.

В публичном каталоге есть два варианта robots/sitemap. На `.com` отдаются
`robots.txt` и `sitemap.xml` (EN/FR); на `.ru` Apache внутренне подставляет
`robots-ru.txt` и `sitemap-ru.xml` под теми же публичными URL `/robots.txt` и
`/sitemap.xml` (RU). В каждом sitemap есть взаимные языковые альтернативы.
Политики сохраняют действующий `noindex` и не включены в sitemap.

Для корректной работы **обновите `.htaccess` вместе со всей сборкой** и направьте
оба домена на один `public_html`. Старые копии `.com/ru/` ведут 301 на `.ru/ru/`,
а `.ru/en/` и `.ru/fr/` — на соответствующий язык `.com`. Нормализуются `www`,
корневые URL, явные `index.html` и завершающие слеши; query сохраняется.
Цели редиректов всегда абсолютные HTTPS, без промежуточного HTTP.
Принудительный HTTP → HTTPS для всего сайта оставьте включённым в панели Timeweb:
не добавляйте без проверки правило по одному `%{HTTPS}` — за TLS-прокси оно может
создать бесконечный редирект. API и неизвестные пути не перенаправляются на лендинг.

После выкладки:

1. Проверьте конечные адреса, отсутствие HTTPS → HTTP и циклов.
2. Откройте исходный HTML: в нём должны быть текст страницы, один H1 и canonical
   нужного домена. Проверьте переключение языков после перехода к якорям.
3. Проверьте `robots.txt` и `sitemap.xml` на обоих доменах. Vite preview не исполняет
   `.htaccess`, поэтому доменные правила проверяются на Apache/Timeweb.
4. Добавьте оба домена в Google Search Console и Яндекс Вебмастер и отправьте
   соответствующий sitemap каждого домена. Проверьте выбранные поисковиком
   канонические URL после переобхода. Смена canonical не даёт мгновенного
   изменения выдачи и не гарантирует позиции.

### Подготовка пакета

`npm run build:timeweb` запускает frontend-тесты и сборку, PHP lint,
PHPUnit и Composer platform check, после чего создаёт
`frontend/timeweb-frontend.zip`. Если локального Composer нет, скрипт
использует Docker Composer 2.

1. В панели Timeweb включите SSL для `.com` и `.ru`, а также принудительный HTTPS.
2. Распакуйте содержимое `timeweb-frontend.zip` непосредственно в публичный
   каталог основного сайта `.com`. В корне должны оказаться `index.html`,
   языковые каталоги, `.htaccess` и каталог `api`.
3. Рядом с публичным каталогом создайте закрытый каталог `private`. Например,
   если `DOCUMENT_ROOT` равен `/home/user/public_html`, конфиг должен лежать в
   `/home/user/private/contact-config.php`.
4. Скопируйте туда `backend/config/contact-config.example.php` под именем
   `contact-config.php` и заполните SMTP login/password, From, Gmail получателя,
   случайный HMAC-секрет длиной не менее 32 символов и абсолютный путь
   `rate_limit_dir`.
5. Создайте каталог rate limiter. Он должен принадлежать пользователю PHP и
   иметь права `0700`; конфиг рекомендуется закрыть правами `0600`.
6. Направьте `.ru`, `www.ru` и `www.com` в тот же сайт. Не настраивайте общий
   редирект `.ru` → `.com`: русская версия должна оставаться на `.ru`.
   Поставляемый `.htaccess` распределяет языковые версии по каноническим доменам.

Тестовая отправка после публикации:

```bash
curl -i 'https://iripurtova-languages.com/api/contact.php' \
  -H 'Origin: https://iripurtova-languages.com' \
  -H 'Content-Type: application/json' \
  --data '{"email":"your-test@example.com","comment":"Timeweb SMTP test","consent":true,"locale":"ru","website":""}'
```

Ожидаемый ответ — HTTP 200 и `{"ok":true,...}`. Затем проверьте доставку в
Gmail и Reply-To. Конфиг должен быть недоступен по публичному URL; его нет ни в
архиве, ни в Git.
