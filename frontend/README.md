# Irina Purtova — frontend

Мультиязычный сайт преподавателя на Vite, HTML, CSS и JavaScript с PHP 8.2 API для контактных форм.

```bash
npm install
npm run dev
npm run test
npm run build
npm run build:timeweb
```

Основной контент, ссылки и заглушки находятся в `src/data/content.js`. Временные Figma URL в коде не используются: изображения и SVG хранятся в `public/assets`.

## Cookies, Яндекс.Метрика и MyTracker

По подтверждению владельца активирован публичный счётчик **113677290** в
`src/metrikaConfig.js` (`enabled: true`). Скрипт загружается только после
отдельного согласия посетителя в баннере. Вебвизор, карта кликов, отслеживание
ссылок и ecommerce остаются выключенными: расширение сбора отдельно не
подтверждено. Активация счётчика не меняет статус проекта политики и не заменяет
её юридическую проверку.

Также подключён **MyTracker / Top.Mail.Ru 3808064** (`src/myTrackerConfig.js`).
На `.ru` и `.com` сначала используется `https://mytopf.com/js/code.js`:
RU/COM в кабинете — выбор CDN, а не домена сайта. При ошибке загрузки COM
пробуется официальный `https://top-fwz1.mail.ru/js/code.js` с тем же ID.
Скрипты загружаются последовательно, просмотр отправляется лишь после успешной
загрузки одного SDK; два предоставленных кода одновременно не устанавливаются.
При проверке 23.10.2026 COM-CDN отдавал просроченный TLS-сертификат (до 08.10),
RU-CDN отвечал по HTTPS без ошибки. Проверку TLS в рабочем коде не отключаем.
`src/siteAnalytics.js` объединяет оба счётчика под отдельным согласием посетителя.
В HTML нет безусловных скриптов и noscript-пикселей.

Перед выкладкой MyTracker:

1. В кабинете приложения проверьте адрес сайта и зеркала `.ru`/`.com`, если
   включена фильтрация по домену. **Автоматические события** оставьте выключенными:
   они включаются на стороне сервиса и могут отслеживать формы, email и мессенджеры
   независимо от вызовов в нашем коде. Изменение этого флага может применяться до 4 часов.
2. Публичные настройки: `VITE_MYTRACKER_ID=3808064` и
   `VITE_MYTRACKER_ENABLED=true`. Значение `false` отключает только MyTracker,
   не Метрику. Не добавляйте в VITE-переменные секреты.
3. Проверьте отсутствие запросов к обоим сервисам до согласия и после отказа.
   После разрешения загружается по одному SDK и отправляется по одному просмотру.
   MyTracker не получает из нашего кода UserID, цели или содержимое заявок.
4. При отзыве разрешения выбор сначала сохраняется, затем страница обновляется:
   у публичного API MyTracker нет документированного метода полного отключения
   уже работающего SDK. Удаление тега script не остановило бы его таймеры.
   Это касается и отзыва в соседней вкладке. Несохранённый ввод может потеряться;
   предупреждение есть в подробностях уведомления. Если SDK не запрашивался,
   обновление не требуется. При заблокированном localStorage новая страница
   снова спросит выбор, но аналитику автоматически не загрузит.

Версия согласия повышена до **3**: старое разрешение только на Метрику не
разрешает MyTracker. Сохранённый выбор связан с ID и флагами обоих сервисов.
При отзыве удаляются доступные сайту `tmr_lvid`, `tmr_lvidTS`, `tmr_detect`
и `_ym`-данные. Cookies сторонних доменов и уже переданные серверные данные
так не удаляются. Настройки хранятся отдельно на каждом домене.

Без ID счётчика или при выключенном флаге соответствующий SDK не загружается.
Когда выключены оба сервиса, показывается информационное уведомление
о локальном хранилище. `i18nextLng` запоминает язык;
`site_cookie_preferences` хранит выбор посетителя 180 дней. Настройки можно
повторно открыть кнопкой в футере. Это не согласие на обработку заявки.

Для выкладки и проверки Метрики:

1. Проверьте настройки счётчика 113677290. Не включайте Вебвизор, автоматические
   цели, аналитику форм, рекламные интеграции или персональные параметры.
2. ID и разрешение на активацию уже заданы в `src/metrikaConfig.js`.
   Для временного отключения задайте `VITE_YANDEX_METRIKA_ENABLED=false`
   в `.env.local`. Для повторного включения — `true`. Заменить ID
   можно через `VITE_YANDEX_METRIKA_ID`. ID публичный, но токены API в
   VITE-переменные добавлять нельзя. Новое включение всё равно требует выбора
   посетителя в баннере.
3. Перезапустите Vite либо выполните новую production-сборку и выложите её.
   Код Метрики из кабинета отдельно в HTML/хостинг не вставляйте: это обойдёт
   контроль согласия. Безусловный noscript-пиксель по той же причине не добавлен.
4. При первом посещении и до выбора, а также после отказа, не должно быть
   запросов к `mc.yandex.ru`. Скрипт грузится только после разрешения.
5. Проверьте разрешение, отказ и отзыв через кнопку в футере. При отзыве
   вызывается `destruct`, удаляются доступные сайту `_ym`-данные. Ранее
   переданные данные и cookies на сторонних доменах этим не удаляются.

Смена ID счётчика, доступности аналитики, версии уведомления или истечение 180 дней требует нового
выбора. Выбор хранится отдельно для `.ru` и `.com`. При блокировке хранилища
решение действует только до обновления страницы. Вебвизор, карта кликов,
отслеживание ссылок и автоматическая отправка хита при инициализации отключены.
Отправляется один хит с URL/referrer без query и hash; данные форм не передаются.

## Политика конфиденциальности

Отдельные страницы `/ru/privacy/`, `/en/privacy/`, `/fr/privacy/` включаются
в production-сборку и архив Timeweb. Полный текст формируется в HTML на этапе
сборки и доступен без JavaScript. Переключатель языка остаётся на документе,
ссылка назад ведёт на лендинг того же языка. Формы открывают документ в новой
вкладке, чтобы не терять введённые данные; ссылка есть также в футере и баннере.

Тексты находятся в `src/data/privacy.js`, общий шаблон —
`src/components/PrivacyPage.js`. Оператор: **Пуртова Ирина Евгеньевна**, физическое
лицо, Россия; обращения: **ipurtova.37@gmail.com**. Домашний или почтовый адрес
не выдуман и не добавлен. Информация о cookies включена в раздел `#cookies`,
отдельный Cookie Policy не требуется для навигации. Упоминание несуществующей
оферты из согласия формы удалено; согласие на аналитику остаётся независимым.

Это **проект для юридической проверки**, а не гарантия соответствия закону.
Страницы помечены `noindex, follow` и содержат заметку о статусе проекта.
Перед публичной выкладкой необходимо:

- Проверить требования к адресу оператора, тексту отдельного согласия на
  обработку данных и уведомлению Роскомнадзора.
- Проверить локализацию и трансграничную передачу при использовании Gmail,
  Telegram/Salebot, действующие условия и фактические настройки этих сервисов.
- Организовать удаление заявок из всех используемых хранилищ, уточнить сроки
  технических журналов и резервных копий; не подменять их сроками заявок.
- После проверки заменить заметку о проекте утверждённой редакцией, обновить
  дату документа и при необходимости снять `noindex`.

Согласованный срок для несостоявшихся заявок — **90 дней после последнего
контакта**. Он относится к содержимому заявок в почте и Telegram/Salebot и
должен быть обеспечен вручную или отдельной автоматизацией. Этот баннер не
удаляет письма, сообщения и анкеты; сроки служебных файлов PHP-бота не меняет.
Счётчики не являются получателями содержимого заявки из нашего кода.
Сроки аналитики нужно отдельно проверить в настройках и документации сервисов.

## Выкладка на Timeweb

`npm run build:timeweb` запускает frontend-тесты и сборку, PHP lint,
PHPUnit и Composer platform check, после чего создаёт
`frontend/timeweb-frontend.zip`. Если локального Composer нет, скрипт
использует Docker Composer 2.

1. В панели Timeweb включите SSL для `.com` и `.ru`, а также принудительный HTTPS.
2. Распакуйте содержимое `timeweb-frontend.zip` непосредственно в публичный
   каталог основного сайта `.com`. В корне должны оказаться `index.html`,
   языковые каталоги, `.htaccess` и каталог `api`.
3. Рядом с публичным каталогом создайте закрытый каталог `private`. Например,
   если `DOCUMENT_ROOT` равен `/home/user/public_html`, конфиг должен лежать в
   `/home/user/private/contact-config.php`.
4. Скопируйте туда `backend/config/contact-config.example.php` под именем
   `contact-config.php` и заполните SMTP login/password, From, Gmail получателя,
   случайный HMAC-секрет длиной не менее 32 символов и абсолютный путь
   `rate_limit_dir`.
5. Создайте каталог rate limiter. Он должен принадлежать пользователю PHP и
   иметь права `0700`; конфиг рекомендуется закрыть правами `0600`.
6. Направьте `.ru`, `www.ru` и `www.com` в тот же сайт либо настройте в панели
   Timeweb постоянные редиректы. В поставляемом `.htaccess` также есть правила
   `301` на `https://iripurtova-languages.com` с сохранением пути и query.

Тестовая отправка после публикации:

```bash
curl -i 'https://iripurtova-languages.com/api/contact.php' \
  -H 'Origin: https://iripurtova-languages.com' \
  -H 'Content-Type: application/json' \
  --data '{"email":"your-test@example.com","comment":"Timeweb SMTP test","consent":true,"locale":"ru","website":""}'
```

Ожидаемый ответ — HTTP 200 и `{"ok":true,...}`. Затем проверьте доставку в
Gmail и Reply-To. Конфиг должен быть недоступен по публичному URL; его нет ни в
архиве, ни в Git.
